2 Relational Database Design & Entity Relationships (ERD)

PostgreSQL 16+
launchup_core.clients Parent Entity
  • PK id: UUID (gen_random_uuid)
  • name: VARCHAR(255)
  • client_type: B2B | B2C
  • tier: Tier 1 | 2 | 3
  • monthly_mrr: NUMERIC(10,2)
  • encrypted_vault: JSONB
  • created_at: TIMESTAMPTZ
client_projects M:N Junction
  • PK/FK client_id: UUID
  • PK/FK project_id: UUID
  • is_primary: BOOLEAN
  • revenue_share_pct: NUMERIC
  • access_permissions: JSONB
  • created_at: TIMESTAMPTZ
launchup_core.projects Managed Project
  • PK id: UUID (gen_random_uuid)
  • name: VARCHAR(255)
  • repository_url: TEXT
  • framework: VARCHAR(50)
  • target_cloud: VARCHAR(50)
  • health_score: INTEGER (0-100)
  • status: Active | Maintenance

3 Zero-Trust Security & Envelope Encryption

NIST SP 800-38D
Phase 1: Ingestion

Key Generation

Data Encryption Key (DEK) is generated in memory. A 96-bit unique cryptographically secure IV is derived specifically for this secret item.

Phase 2: AES-256-GCM

Authenticated Cipher

The plaintext is encrypted with AES-256-GCM yielding ciphertext and a 128-bit integrity authentication tag preventing bit-flipping attacks.

Phase 3: Envelope Wrapping

Zero Client Exposure

The DEK is wrapped with the Key Encryption Key (KEK) stored exclusively in KMS. No decrypted keys are ever transmitted to the frontend browser.

4 Zero-Downtime Multi-Cloud Rollback Engine

< 3s Rerouting

When an anomaly or health degradation is detected on production, the DevOps engineer initiates a 1-click rollback:

Step 1: Checkpoint Lookup Fetch prior healthy deployment commit digest from time-series logs.
Step 2: Routing Shift Swap target ingress (Vercel alias, ECS Task Revision, Cloud Run split).
Step 3: Health Probe Validate HTTP 200 OK probe and broadcast system alert resolution.
